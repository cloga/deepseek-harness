# 发布脚本

[English](README.md) | 中文

本参考文档负责说明 [release.yml](../../.github/workflows/release.yml) 中的包演练和已退役的 Core/Web GitHub Release 入口。[families.ts](families.ts) 负责包成员、版本、载荷策略和发布顺序。独立的 [npm 发布器](../../.github/workflows/release-publish.yml) 保持不变。

## 包演练

工作流在拉取请求、master 推送和手动触发时运行依赖布局检查、官方构建、包打包和打包安装验证。它仅包含 `dependencies` 和 `pack` 两个任务、仓库读取权限，以及按工作流和引用取消旧运行的设置。现有托管运行器和受信任自托管运行器的选择保持不变。它不接受发布输入，也没有 GitHub Release 写入器、封装步骤或发布令牌。

生成的 dsh 压缩包和发布顺序文件作为 CI 产物保留七天。Vendored 框架和 Landlock 入口压缩包用于打包安装验证，但不会随该产物上传。这些包产物既不是 Windows Desktop 安装器，也不是离线安装依赖闭包；可选原生包和注册表依赖仍来自外部。

## Fork 交付与退役入口

对于 `cloga/deepseek-harness`，默认面向用户的交付是通过 `dsh-desktop-v<version>` 渠道发布并经过验证的 Windows Desktop 安装器。用于该产品的 Core/Web 修改必须通过经过资格验证的 Desktop 源码和发布流程交付。其他公开交付类型需要用户另行明确授权，并记录在所依据的发布计划或 Issue 中；一般性的发布批准、正确的包校验和或成功的演练并不构成该授权。[Issue #90](https://github.com/cloga/deepseek-harness/issues/90) 负责本次纠正；此隔离源码不会引入 fork 的 Desktop 实现。

[github-artifacts.ts](github-artifacts.ts) 是只会拒绝执行的兼容入口。任何调用，包括原来的 `guard` 和 `publish` 命令、缺失或未知参数，以及此前满足准入条件的环境选择器，都会以非零状态退出并输出退役说明。它不读取凭据或产物，不发起网络请求，不生成日志或封装记录，也不修改发行版、标签或文件。旧写入器、证据读取器和准备实现已删除，而不是保留在启用开关之后。没有强制执行或恢复选项。

## 既有标签与发行版

此源码修改不会改变旧不可变标签中的代码，不会停止历史工作流运行、删除 Release、移动标签或替换任何已发布字节。不要从旧引用触发已退役的写入器。历史恢复仍受其既有的前次写入尝试拒绝机制和不可变标签不可复用限制约束；这些限制不能代替本次源码退役，也不得绕过。撤回和替代必须遵循另行授权的发布流程，保留受保护标签，并在退役旧 Release 前验证替代版。

## 验证范围

现有脚本测试执行面包含 `github-artifacts.spec.ts`。它使用旧环境和空环境，通过普通 Node 调用拒绝入口，拦截网络和文件写入尝试，并检查产物保持不变且没有生成日志。工作流回归会拒绝重新引入发布输入、任务、权限、令牌、防护或封装命令，以及缺失构建或打包安装验证的变更，同时保留运行器路由和 npm 发布断言。这些检查不证明完整构建、真实 GitHub 触发行为、Windows 安装、已发布产物完整性或 Desktop 运行时验收。
