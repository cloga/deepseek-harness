# Agent Note: 通过系统浏览器打开 Desktop 网页链接

Status: implemented

[English](2026-09-20-desktop-external-links.md) | 中文

## Problem

拒绝所有弹出窗口并取消所有外部导航能够保护应用自有文档，却让普通网页链接无处打开。只修改一个 provider 的 anchor target 无法修复同时拒绝两条打开路径的桌面壳。维护版桌面壳还负责恢复操作，必须将其与普通外部导航分开处理。

## Decision

[窗口导航](../../../../apps/desktop/src/window-navigation.ts)为产品窗口和插件窗口提供同一策略。它遵循官方 Desktop 的行为，将 HTTP 和 HTTPS 目标交给系统浏览器，同时拒绝创建 Electron 弹出窗口。弹窗请求和同窗口导航都先解析目标，再发送其规范化 URL。格式错误的输入和其他外部 scheme 仍被阻止；不引入 shell 命令或新的渲染进程 IPC。

内部 `dsh-app:` 导航保留在应用内。`dsh-recovery:` 导航被阻止，并且只委托给现有恢复负责人；原有文档身份、操作、权限和进行中状态检查全部保留。弹窗形式的恢复请求不执行恢复。此策略不改变 Web 客户端的可选 iframe 预览或文件链接路由。

浏览器打开操作的 Promise 拒绝和同步失败使用同一个脱敏回调。所属窗口仅在仍存活时显示现有 locale 的建议。报告失败也会被接住，不记录原始错误或目标，因为请求 URL 可能包含授权数据。成功交给操作系统不证明页面已加载或授权已成功。

## Alternatives considered

**逐个把链接改成 `_self`。** 其他链接和程序化打开仍然损坏，而且 provider UI 会与桌面壳的特定行为耦合。

**允许 Electron 弹窗或让产品窗口跳离应用。** 两种做法都会扩大渲染进程能力，并可能替换或分离应用自有 UI。

**替换维护版桌面壳或升级 Core。** 外部导航是桌面壳负责的缺项；修复它不要求改变运行时、插件、恢复或更新的归属。

## Consequences

共享策略修复两条打开路径，不改变 preload 协议，也不削弱 sandbox 设置。不支持的 URI scheme 继续不可用，不会启动任意已注册应用。启动集成测试保留恢复行为，导航定向测试覆盖拒绝、格式错误目标、窗口独立操作和脱敏失败报告。隔离 Electron 渲染进程测试使用替代的操作系统打开器确认点击分发；它不代表已安装产品或真实默认浏览器的验收。
