# Agent Note: 已命名的空白 Session 保持可导航

Status: implemented

[English](2026-09-15-titled-blank-session-navigation.md) | 中文

## 问题

用户或集成可以在首次轮次前为顶层 Session 写入持久化标题，把它预创建为后续工作入口。Workspace 浏览器曾把每个非当前空白 Session 都当作可丢弃的新会话占位行，因此既隐藏该行，又用本地化占位文案替换其持久化标题。用户若不先添加一个无关模型轮次，就无法导航到这个已准备的 Session。

## 决策

Workspace 浏览器用 `SessionSummary.title !== undefined` 表示明确保留空白 root 作为导航目标的意图。分组与平铺视图显示其持久化标题，元数据搜索可以匹配该标题或其 Workspace。未命名空白 Session 仍只在被选中时显示，并继续使用本地化「新会话」标签。「新会话」创建只会复用这些未命名空白行，不会复用为后续工作保留的已命名 Session。既有子代理和归档排除规则保持不变。

有明确标题的空白行计入折叠 Workspace 的五条普通行额度。只有当前选中的未命名「新会话」不占该额度。内容搜索结果不会向空白 Session 附加摘要，因为其日志中没有可搜索的已完成对话。

## 考虑过的替代方案

**启动一个合成轮次。** 这会让 Session 变为非空白，但会添加无关历史，可能调用模型，并通过修改数据来修复导航。

**显示所有空白 Session。** 这会暴露被放弃的临时行，并削弱「新会话」复用语义。

**依赖 Schedule 投影。** 预创建 Session 可能来自内置 Schedule 能力之外的集成，外部调度器也不必写入 Schedule 事件词汇。持久化标题是每个列表行本来就有、并由本包拥有的意图信号。

## 后果

已准备且命名的 Session 无需唤醒 Agent 或追加事件即可被发现。树派生、行渲染、折叠行计数和元数据搜索共同区分未命名临时空白行与有明确标题的空白 root。单元与渲染组件测试覆盖命名可见性、本地化临时行、折叠、搜索、归档排除和子代理排除。
