# Agent Note: Qualify managed Desktop Copilot maintenance separately from Core promotion

Status: implemented

English | [中文](2026-09-20-managed-desktop-copilot-maintenance.zh.md)

## Problem

The managed Windows Desktop must advance its release-owned Copilot package without silently promoting the Core baseline or carrying companion behavior after official Core provides complete parity. Plugin publication, Core compatibility, packaged Desktop behavior, and installed-machine activation are separate evidence.

The reviewed Desktop `0.1.6-alpha.1.cloga.18` / sequence 30 plan pins immutable [Copilot `0.4.0-alpha.35`](https://github.com/cloga/dsh-github-copilot/releases/tag/v0.4.0-alpha.35), retaining Core `0.1.6-alpha.1`. Its complete exact-source lock determines the plugin artifact. Plugin publication and alpha.1/alpha.2 compatibility do not replace Desktop qualification or qualify the separately owned Core alpha.2 adaptation.

## Decision

A Copilot maintenance release keeps the reviewed Core version and exact dependency registry while replacing the complete verified-release source lock. The plan binds the release tag, asset identifiers, byte sizes, SHA-256, SHA-512 SRI, target source, and checksum manifest. Tests compare the complete provisioning object rather than selected fields. The explicitly approved Core change is Client layout only: backport official alpha.2's public shared composer dock row with wrapping while retaining alpha.1's ContextMeter placement, Host behavior, token accounting, and billing. This decision refines provider-release selection and official-first review; the [verified release transaction](2026-09-15-desktop-verified-release-plugin-transactions.md) remains authoritative for acquisition, staging, ownership, rollback, and receipts.

Initial and restart settings acceptance stays signed out and read-only. It requires positive account and search readiness before recording retired Model roles absence, checks Manage without the retired compatibility disclosure, provider-only **Search provider** and **Fallback provider** controls, the registered catalog, exact provisioning inventory, and restart-stable receipts. `settingsAcceptance` contains the two actual schema-3 observations with `retiredModelRolesAbsent: true`; historical schema-2 `modelRolesViewLoaded` / `currentWorkspaceReadOnly` evidence cannot establish retirement and is never relabeled. The retired card has no screenshot. Acceptance never saves settings, initiates OAuth, opens a verification address, calls a model or search provider, or changes a user profile. Copilot's own synthetic Client tests cover Desktop same-window verification navigation, Web new-tab behavior, and selectable manual URL handoff; Desktop acceptance does not repeat those actions against an operator browser.

Alpha.28 retains plugin-owned independent prompt and combined input/output admission while signaling the official bounded compaction path. Alpha.29 retains provider-only routing, one routing-namespace compare-and-swap, one distinct final fallback, and account-owned Copilot search-model resolution without a model prerequisite. Alpha.30 retains the existing Desktop external-navigation handoff and manual selectable verification address. Alpha.31 delegates OAuth renewal and credential persistence to native ownership while retaining bounded managed-route HTTP 401 proof retirement. Alpha.32 adds normalized account quota snapshots and optional Session-scoped composer presentation without replacing the native Context meter or inventing Session credits. These behaviors remain plugin-owned where official Core does not provide equivalent policy.

Alpha.33 repaired the Client's required `useSession(selector)` call without changing Core. Its positive synthetic-Session/quota fixture remains separate from native-Session geometry acceptance; the [release-channel decision](2026-09-15-fork-owned-windows-desktop-release-channel.md#positive-packaged-plugin-acceptance) owns that renderer fixture's isolation and evidence limits. Core alpha.1 and alpha.2 already provide the selector hook and Slot error boundary; the plugin conforms to those official APIs rather than adding a Core fallback.

Alpha.34 retired the Model roles card, legacy Settings entry, role selectors, and new dedicated-root creation. Alpha.35 preserves that retirement and the compatibility-only Host support for existing histories; layout maintenance does not restore role settings writes or Host features.

After the signed-out/no-Session initial and restart checks and isolated synthetic quota fixture, a third application phase seeds one test-owned persisted Session through packaged public Session, JSONL persistence, and WorkspaceRegistry APIs. A fresh temporary home and exclusive ownership marker constrain the write. Synthetic `github-copilot` / `synthetic-layout-model` history supplies 10 input, 90 cache-read, and 5 output tokens without inference. The actual application measures InputBar, StatsPills, and the released Client at 1280 and 400 pixels, requires inline placement after Cache hit at the wide width and non-overlap/containment at both widths, and checks matching font size, line height, and color. Native time, Token usage, and signed-out Copilot dialogs must open and dismiss; the Copilot dialog omits Session credits and unavailable reset dates and restores trigger focus without a forced refresh. Hash-bound geometry evidence identifies signed-out Host quota state; it is neither live quota nor ready numeric credits.

## Official-first comparison

The exact official review target is [Core `0.1.6-alpha.2`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.2). The plugin's alpha.35 [alpha.2 comparison](https://github.com/cloga/dsh-github-copilot/blob/v0.4.0-alpha.35/docs/official-first-016-alpha2.md), [compaction decision](https://github.com/cloga/dsh-github-copilot/blob/v0.4.0-alpha.35/docs/copilot-compaction.md), and [account-usage contract](https://github.com/cloga/dsh-github-copilot/blob/v0.4.0-alpha.35/docs/copilot-usage.md) provide source-level policy evidence; artifact verification remains separate.

| Area | Official alpha.2 support | Decision and migration condition |
|---|---|---|
| OAuth, normal Copilot transport, strict Remote factories, service tracing, serialized initialization, native subagent descriptors | Complete primitives used by alpha.35 | Continue official primitives. Retire the alpha.1 compatibility bridge only after the supported Core floor advances and packaged alpha.2 acceptance passes. |
| Managed HTTP 401 recovery | Native `Models.getAuth()` and canonical credentials own renewal and persistence; Core does not own Copilot route proof, identical-token rejection, cooldown, or generation races | Retain only bounded managed-route rejection policy. Retire it when official provider transport exposes equivalent provider-scoped rejected-token renewal and Desktop qualification. |
| Account quota and composer usage | Public Remote codecs and the native Context meter are official primitives; Core does not expose complete provider-reported Copilot quota, credits, or Session attribution | Retain normalized account snapshots and optional Copilot Session UI. Retire them when official APIs provide equivalent account semantics and a supported Session-scoped composer seam. |
| Composer dock placement | Official shared flex dock and intrinsic-width statistics group support adjacent public dock entries | Backport only Client layout with wrapping to alpha.1; keep ContextMeter placement and token semantics. Retire the adaptation after a separately qualified alpha.2 upgrade passes the same native geometry checks. |
| Account-owned model discovery | Partial; the official catalog does not replace authenticated Copilot account refresh and ownership proof | Retain discovery, proof, cache, cooldown, and route handling until official account and entitlement discovery preserves supported endpoint, capability, route, Session, and profile state. |
| Cross-provider search routing | Partial; official provider selection does not supply the complete initiating-Chat, explicit primary, one-final-fallback, cancellation, account-invalidation, disclosure, and legacy-migration policy | Retain the provider-only companion policy until official settings and runtime provide equivalent behavior and migration tests. |
| Compaction and recovery | Partial; official bounded compaction is authoritative, while Copilot-specific independent admission and summary-purpose defaults are not official policy | Reuse official recovery. Retire companion admission/defaults only after official behavior enforces equivalent provider budgets and oversized-history acceptance. |
| Plugin Manager and runtime unload | Available in alpha.2 | Prefer those primitives only after the separate alpha.2 Desktop lane qualifies exact source conversion, ownership retention, staged health, rollback, recovery, and packaged runtime behavior. |
| Desktop verification navigation | Existing Desktop navigation owns same-window external handoff; Copilot still owns provider-specific presentation and manual recovery | Retire plugin glue only when official provider/account UI supplies equivalent Desktop handoff, manual URL, cancellation, and packaged acceptance. |

The alpha.34 Model roles retirement is a product decision, not a claim of official parity. No further companion feature is removed merely because an official primitive has a similar name. The separately owned alpha.2 draft remains independent; the explicitly approved Client layout backport does not merge, rebase, or absorb its other changes.

## Publication evidence boundary

Copilot alpha.35's [post-merge run 35603503257](https://github.com/cloga/dsh-github-copilot/actions/runs/35603503257) passed source, compatibility, build, and immutable GitHub publication checks; its historical failure was the immediate npm integrity readback. The independent [read-only verifier run 35605111730](https://github.com/cloga/dsh-github-copilot/actions/runs/35605111730) passed npm/GitHub byte identity and alpha-tag checks. The exact release assets and SHA-512 integrity were independently checked without republishing. This qualifies the plugin bytes, not the still-separate Desktop installer or local activation.

Historical Copilot alpha.33 post-merge [run 35559690050](https://github.com/cloga/dsh-github-copilot/actions/runs/35559690050) passed compatibility, exact alpha.1/alpha.2 Windows/Ubuntu, verification, packaging, and GitHub publication; immediate npm visibility verification failed. Independent read-only verifier [run 35560198211, attempt 2](https://github.com/cloga/dsh-github-copilot/actions/runs/35560198211/attempts/2) passed npm/GitHub same-byte and alpha-tag verification. These runs qualify alpha.33 only, not alpha.35 or Desktop `.cloga.18`. Each maintenance release requires its own immutable plugin lock and Desktop qualification; Desktop consumes published bytes rather than republishing or rewriting the plugin release.

Neither a reviewed target nor the acceptance implementation establishes published artifact verification. Historical evidence and synthetic usage or geometry checks do not establish live OAuth, account quota, model inference, hosted search, fallback charges, local installation, or activation. Those operations require separate authorization and must not be inferred from CI, package hashes, or packaged signed-out acceptance.

## Alternatives considered

**Promote Core alpha.2 with the plugin pin.** Compatibility is not packaged qualification. Combining the lanes would absorb separately owned work and lose a narrow maintenance rollback point.

**Delete companion behavior whose official primitive has a similar name.** Similar names do not establish policy, persistence, cancellation, or migration parity. Removal waits for the conditions in the comparison table.

**Exercise OAuth or search during Desktop packaging.** That would require account state, may incur charges, and would mutate acceptance state. Immutable bytes plus signed-out UI, inventory, restart, and isolated synthetic-Session checks are the release gate; live-provider checks remain separate.

## Consequences

Each managed Copilot update advances the Desktop version and sequence even when Core and shell code remain unchanged. The packaged release carries the exact plugin source and dependency registry, while Windows Ops can independently pin the resulting Desktop assets. A later Core promotion must refresh this comparison and satisfy its own packaged rehearsal before companion behavior is migrated or retired.
