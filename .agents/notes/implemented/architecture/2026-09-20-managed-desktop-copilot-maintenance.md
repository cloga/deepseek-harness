# Agent Note: Qualify managed Desktop Copilot maintenance separately from Core promotion

Status: implemented

English | [中文](2026-09-20-managed-desktop-copilot-maintenance.zh.md)

## Problem

The managed Windows Desktop must advance its release-owned Copilot package without silently promoting the Core baseline or carrying companion behavior after official Core provides complete parity. Plugin publication, Core compatibility, packaged Desktop behavior, and installed-machine activation are separate evidence.

Copilot-only maintenance preserves the reviewed Core baseline independently of plugin selection. The alpha.2 Desktop candidate incorporates immutable [Copilot `0.4.0-alpha.35`](https://github.com/cloga/dsh-github-copilot/releases/tag/v0.4.0-alpha.35) and its maintenance acceptance requirements. Plugin publication and declared alpha.1/alpha.2 compatibility do not qualify the Core alpha.2 Desktop adaptation.

## Decision

A Copilot maintenance release keeps the reviewed Core version and exact dependency registry while replacing the complete verified-release source lock. The plan binds the release tag, asset identifiers, byte sizes, SHA-256, SHA-512 SRI, target source, and checksum manifest. Tests compare the complete provisioning object rather than selected fields. The Client layout adaptation uses the public shared composer dock with wrapping while preserving the target Core's ContextMeter placement, Host behavior, token accounting, and billing. Alpha.2 already owns the dock and below-card ContextMeter; its adaptation adds wrapping and safe empty-outlet handling rather than importing alpha.1's whole composer. This decision refines provider-release selection and official-first review; the [verified release transaction](2026-09-15-desktop-verified-release-plugin-transactions.md) remains authoritative for acquisition, staging, ownership, rollback, and receipts.

Initial and restart settings acceptance stays signed out and read-only. It requires positive account and search readiness before recording retired Model roles absence, checks Manage without the retired compatibility disclosure, provider-only **Search provider** and **Fallback provider** controls, the registered catalog, exact provisioning inventory, and restart-stable receipts. `settingsAcceptance` contains two actual schema-3 observations with `retiredModelRolesAbsent: true`; historical schema-2 role-loading evidence is never relabeled. The retired card has no screenshot. Acceptance never saves settings, initiates OAuth, opens a verification address, calls a model or search provider, requests live quota, or changes a user profile. Copilot's synthetic Client tests separately cover Desktop same-window verification navigation, Web new-tab behavior, and selectable manual URL handoff; Desktop acceptance does not repeat those actions against an operator browser.

Alpha.28 retains plugin-owned independent prompt and combined input/output admission while signaling the official bounded compaction path. Alpha.29 retains provider-only routing, one routing-namespace compare-and-swap, one distinct final fallback, and account-owned Copilot search-model resolution without a model prerequisite. Alpha.30 retains the existing Desktop external-navigation handoff and manual selectable verification address. Alpha.31 delegates OAuth renewal and credential persistence to native ownership while retaining bounded managed-route HTTP 401 proof retirement. Alpha.32 adds normalized account quota snapshots and optional Session-scoped composer presentation without replacing the native Context meter or inventing Session credits. These behaviors remain plugin-owned where official Core does not provide equivalent policy.

Alpha.33 repairs the Client's required `useSession(selector)` call without changing Core. The original alpha.32-to-alpha.33 archive comparison preserves dependencies, exports, all 36 capability IDs and compaction behavior; its Host JavaScript changes only the embedded version and four other runtime JavaScript files remain identical. Positive synthetic-Session acceptance supplements signed-out checks with the actual packaged renderer and released Client. It retains inherited-versus-explicit-absent Session binding, four eligible quota reads, disposal while visible and restoration of the original application. The [release-channel decision](2026-09-15-fork-owned-windows-desktop-release-channel.md#positive-packaged-plugin-acceptance) owns isolation and evidence limits. Core alpha.1 and alpha.2 already provide the selector hook and Slot error boundary; the plugin conforms rather than adding a Core fallback.

Alpha.34 retires the Model roles card, legacy Settings entry, role selectors, and new dedicated-root creation. Alpha.35 preserves that retirement and compatibility-only Host support for existing histories; layout maintenance does not restore role settings writes or Host features. Original alpha.33-to-alpha.35 comparison preserves all 36 capability IDs, exact alpha.2 peer admission, usage Session binding and compaction behavior. Host changes also include role retirement and optional reset normalization, so the alpha.33 version-only Host finding must not be transferred to alpha.35.

After initial/restart and synthetic positive checks, a third application phase seeds one test-owned persisted Session through packaged public Session, JSONL persistence, and WorkspaceRegistry APIs in the same owned temporary home. An exclusive ownership marker constrains the write. Synthetic `github-copilot` / `synthetic-layout-model` history supplies 10 input, 90 cache-read, and 5 output tokens without inference. The actual application measures InputBar, StatsPills, and the released Client at 1280 and 400 pixels, requiring inline placement after Cache hit at the wide width, horizontal containment/non-overlap at both widths, and matching font size, line height, and color. Native time, Token usage, and signed-out Copilot dialogs must open, dismiss with Escape and restore focus. The Copilot dialog omits Session credits and unavailable reset dates without a forced refresh. Full owned source/run identity and original-byte hashes bind these provisional observations; they are neither live quota nor ready numeric credits. Inspection errors are sealed before deliberate shutdown, and the same outer cleanup owner controls every phase. The [Desktop test reference](../../../../apps/desktop/tests/README.md#verification-hosted) owns the versioned completion protocol and separate installed-upgrade requirements.

## Official-first comparison

The exact official review target is [Core `0.1.6-alpha.2`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.2). The plugin's alpha.35 [alpha.2 comparison](https://github.com/cloga/dsh-github-copilot/blob/v0.4.0-alpha.35/docs/official-first-016-alpha2.md), [compaction decision](https://github.com/cloga/dsh-github-copilot/blob/v0.4.0-alpha.35/docs/copilot-compaction.md), and [account-usage contract](https://github.com/cloga/dsh-github-copilot/blob/v0.4.0-alpha.35/docs/copilot-usage.md) provide source-level policy evidence; artifact verification remains separate.

| Area | Official alpha.2 support | Decision and migration condition |
|---|---|---|
| OAuth, normal Copilot transport, strict Remote factories, service tracing, serialized initialization, native subagent descriptors | Complete primitives used by alpha.35 | Continue official primitives. Retire the alpha.1 compatibility bridge only after the supported Core floor advances and packaged alpha.2 acceptance passes. |
| Managed HTTP 401 recovery | Native `Models.getAuth()` and canonical credentials own renewal and persistence; Core does not own Copilot route proof, identical-token rejection, cooldown, or generation races | Retain only bounded managed-route rejection policy. Retire it when official provider transport exposes equivalent provider-scoped rejected-token renewal and Desktop qualification. |
| Account quota and composer usage | Public Remote codecs and the native Context meter are official primitives; Core does not expose complete provider-reported Copilot quota, credits, or Session attribution | Retain normalized account snapshots and optional Copilot Session UI. Retire them when official APIs provide equivalent account semantics and a supported Session-scoped composer seam. |
| Composer dock placement | Official shared flex dock and intrinsic-width statistics group support adjacent public dock entries | Keep the official alpha.2 dock and ContextMeter placement; retain wrapping and layout-neutral empty-outlet handling until official geometry passes equivalent wide/narrow native checks. The alpha.1 backport is not an alternate alpha.2 owner. |
| Account-owned model discovery | Partial; the official catalog does not replace authenticated Copilot account refresh and ownership proof | Retain discovery, proof, cache, cooldown, and route handling until official account and entitlement discovery preserves supported endpoint, capability, route, Session, and profile state. |
| Cross-provider search routing | Partial; official provider selection does not supply the complete initiating-Chat, explicit primary, one-final-fallback, cancellation, account-invalidation, disclosure, and legacy-migration policy | Retain the provider-only companion policy until official settings and runtime provide equivalent behavior and migration tests. |
| Compaction and recovery | Partial; official bounded compaction is authoritative, while Copilot-specific independent admission and summary-purpose defaults are not official policy | Reuse official recovery. Retire companion admission/defaults only after official behavior enforces equivalent provider budgets and oversized-history acceptance. |
| Plugin Manager and runtime unload | Available in alpha.2 | The alpha.2 candidate adopts those primitives in source; packaged qualification of exact source conversion, ownership retention, staged health, rollback, recovery, and runtime behavior remains pending. |
| Desktop verification navigation | Existing Desktop navigation owns same-window external handoff; Copilot still owns provider-specific presentation and manual recovery | Retire plugin glue only when official provider/account UI supplies equivalent Desktop handoff, manual URL, cancellation, and packaged acceptance. |

Alpha.34's Model roles retirement is a product decision, not a claim of official parity. No further companion feature is removed merely because an official primitive has a similar name. The [official-first Desktop assessment](../../proposed/architecture/2026-09-18-official-first-desktop-safety.md) owns alpha.2 source adoption and remaining artifact qualification; incorporating this maintenance work does not establish packaged or installed acceptance.

## Publication evidence boundary

Copilot alpha.35's [post-merge run 35603503257](https://github.com/cloga/dsh-github-copilot/actions/runs/35603503257) passed compatibility, exact alpha.2 Windows/Ubuntu, build, and immutable GitHub publication checks; the overall run failed at npm publication/integrity readback. The [read-only verifier run 35605111730](https://github.com/cloga/dsh-github-copilot/actions/runs/35605111730) reports success. Independent original-asset review checked the immutable GitHub tarball, checksum manifest, source/tag/tree binding and SHA-512 integrity, but did not acquire that verifier's receipt archive and makes no independent npm attestation. Plugin-byte verification does not qualify the Desktop installer or local activation.

Historical alpha.33 [run 35559690050](https://github.com/cloga/dsh-github-copilot/actions/runs/35559690050) and later [verifier run 35560198211, attempt 2](https://github.com/cloga/dsh-github-copilot/actions/runs/35560198211/attempts/2) concern alpha.33 only, not alpha.35 or a new Desktop release. Its original-asset review likewise verified GitHub bytes without acquiring the npm verifier receipt. Every maintenance release requires its own immutable plugin lock and Desktop qualification; Desktop consumes published bytes rather than republishing or rewriting the plugin release.

Neither a reviewed target nor the acceptance implementation establishes published Desktop verification. Historical evidence and synthetic usage or geometry checks do not establish live OAuth, account quota, model inference, hosted search, fallback charges, local installation, or activation. Those operations require separate authorization and must not be inferred from CI, package hashes, or packaged signed-out acceptance.

## Alternatives considered

**Treat the plugin pin as Core alpha.2 qualification.** Compatibility is not packaged qualification. A Copilot-only maintenance release preserves a narrow rollback point; a Core-upgrade candidate that incorporates it still requires its own artifact qualification.

**Delete companion behavior whose official primitive has a similar name.** Similar names do not establish policy, persistence, cancellation, or migration parity. Removal waits for the conditions in the comparison table.

**Exercise OAuth or search during Desktop packaging.** That would require account state, may incur charges, and would mutate acceptance state. Immutable bytes plus signed-out UI, inventory, restart, and isolated synthetic-Session checks are the release gate; live-provider checks remain separate.

## Consequences

Each managed Copilot update advances the Desktop version and sequence even when Core and shell code remain unchanged. The packaged release carries the exact plugin source and dependency registry, while Windows Ops can independently pin the resulting Desktop assets. A Core promotion refreshes this comparison and requires its own packaged and installed rehearsal before companion behavior is migrated or retired.
