# Agent Note: 通过就绪信号同步慢速 spill 测试

Status: implemented

[English](2026-09-19-spill-readiness-barriers.md) | 中文

## 问题

基于子进程的 spill 回归需要确认：前一个超大结果仍在等待 spill 后端时，后续工具派发已经开始。轮询辅助函数隐含的一秒期限也包含进程初始化，因此竞争激烈的 Windows 覆盖率 worker 可能在被测行为可观测之前就失败。

## 决策

[慢速 spill 回归](../../../../packages/spill/spill-policy/tests/spill-policy.spec.ts)等待自有的后端进入信号和派发开始信号。结果交付用例保持后端阻塞，直到观察到后续派发；断言还要求超大结果的保存或结算均未完成。积压上限用例观察第二次和第三次保存进入的里程碑，保留第三次派发尚未开始的断言，并预先分配释放门闩，避免迟到的保存阻塞清理。释放后端后执行原有结果与结算断言。失败和超时清理会释放自有门闩，并等待执行结束。

用例使用已有的测试或运行通道期限，不再附加轮询期限。生产 spill 行为、进程启动行为、并发限制和覆盖率要求均保持不变。

## 考虑过的替代方案

**增大任意轮询超时。** 更长的时钟余量仍把进程启动与派发顺序混为一谈，也可能在另一种竞争程度下失败。

**跳过回归或串行执行覆盖率。** 两者都不能保留结果交付独立于延迟日志整形的证据。

**修改生产 spill 顺序。** 当前失败不能证明生产顺序存在缺陷；回归保留原有顺序要求。

## 后果

测试依赖实际进度事件，而不是调度器的时间上界。如果运行时等待 spill 完成后才交付程序值，就无法在门闩关闭时满足后续派发观测。即使观测失败，清理仍负责异步工作的生命周期。这是测试同步证据，不是终端用户延迟基准。保留的第三次派发尚未开始这一瞬时断言，并不能独立证明测试能检出积压上限算法的变异。
