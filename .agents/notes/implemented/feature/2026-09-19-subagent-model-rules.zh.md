# Agent Note: 创建时 subagent 模型规则

Status: implemented

[English](2026-09-19-subagent-model-rules.md) | 中文

## 问题

用户可能希望交互式父模型把实现工作委派给另一个模型，而不改变父 Session 的选择，也不授予模型任意选择子模型路由的权限。每个工具的固定默认值无法表达按直接父级实际路由匹配的例外规则。另建规划／执行工作流又会引入无关的模型锁定和工具限制。

原生子级创建还会记录后续恢复所需的信息。发布后再选择另一条路由，可能导致 descriptor 与首次请求不一致。异步验证后再次解析父级，也可能继承另一次父模型选择的思考强度。

## 决策

Host 所有的 `subagent.modelRules` 设置保存精确的父级／子级 provider-model 对。空规则保留继承行为。原生运行时仅对原本会继承父模型、支持模型配置的新建子级应用一条匹配规则。调用方提供的 provider、model 或 reasoning effort，以及 provider 自有的路由默认值，仍然优先。不支持配置 Host Agent 选项的外部产品保留自己的模型控制权。

规则是用户所有的默认值，不是允许模型自行选择路由的权限。现有 Session 授权仍会在创建前拒绝禁用、格式错误或未获允许的显式选择。仅指定思考强度的请求保留其已授权路由，不会把该强度应用到规则选出的另一模型。

运行时在异步目标验证前捕获规则和完整的实际选项。匹配目标使用原生精确模型解析；目标不可用、取消或 provider 变化均拒绝创建，不选择回退模型。进程内一次性 provider 直接接收捕获的选项和分离的委派权限，不再读取父级。沙箱与审批策略在模型预检前捕获，防止父级后续的权限变化影响已经开始请求创建的子级。可继续执行的子级在既有 descriptor 中记录所选路由；后续消息和冷恢复不会重新应用当前规则。

用户编写的规则也适用于兼容的 fork provider。这不同于[模型选择的 subagent 路由](2026-08-18-model-selected-subagent-routes.zh.md)中的模型侧 fork 选择限制：默认值由用户决定，模型并未获得新的路由选择权限。设置会说明，改变 fork 子级的模型可能失去继承前缀的 KV Cache 复用，并需要重新处理历史；不保证成本更低。

原生设置卡通过一次带版本校验的共享命名空间修改保存规则和委派限制。模型选择权限保留独立命名空间。UI 标明设置已保存，不据此声称已有子级使用了这些设置；实际选择仍以子级请求记录为依据。

## 考虑过的替代方案

**在专用工作流中固定父模型。** 拒绝，因为这里需要决定的是子级默认值，而不是规划角色或主对话的限制。

**改写原生工具参数或替换委派工具。** 拒绝，因为无需改变模型侧调用，而且这样可能让权限检查和日志参数偏离真正创建子级的操作。由服务所有的默认值覆盖原生调用方，无需替换其工具。

**改变已发布子级的模型。** 拒绝，因为创建 descriptor 必须与首次请求一致，当前设置的变化也不能改写已有子级。

**把所有后端都视为继承 Host 模型。** 拒绝，因为外部产品及 provider 自有路由默认值各有模型控制权。全局规则不能禁用向这些后端进行的普通委派。

## 影响

父 Session 保持不变，配置规则影响未来创建，而不是已有子级。匹配到不可用目标时明确失败，不会静默继承。预检期间适配器拓扑发生并发变化时会保守拒绝本次预检，包括无关适配器的变化；目录稳定后，调用方可以重试。不会通过自动重试另建子级。

验证覆盖原生工具授权、直接父级的精确匹配、跨设置和父级变化保留捕获选项、实际 spawn／fork 请求、descriptor 与冷恢复一致性、外部 provider 保持不变，以及原子设置修改。SDK 记录会话场景比较父级和子级的请求记录，而不依赖助手文本来判断所选模型。
