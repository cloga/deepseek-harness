# Agent Note: 持续可见的 Desktop 更新提示

Status: implemented

[English](2026-09-17-persistent-desktop-update-notice.md) | 中文

## 问题

仅在启动时检查会错过 Desktop 持续运行期间发布的版本。菜单入口容易被忽略，而自动弹出安装对话框会打断工作。更新状态需要一个不依赖当前会话的可见位置，同时不能赋予 Web 渲染进程包管理权限。

## 决策

[官方优先迁移提案](../../proposed/architecture/2026-09-18-official-first-desktop-safety.zh.md)部分取代本决策。Fork 的协议 2 提示栏、布局适配器和独立通知轮询退役，改用官方设置中的 `DesktopUpdateIndicator` 和收起状态徽标。本记录保留不中断的发现与壳权限理由，不构成进行中的安全迁移验收，也不把旧提示栏描述为受支持的 UI。

Electron 负责更新发现与安装。官方协议 1 桥接暴露 `status`、`open` 和可移除订阅。渲染器不能选择更新 URL、路径、版本或安装参数；打开更新 UI 不授权安装。插件管理属于共享 Web PluginManager，而非更新 IPC。[Desktop README](../../../../apps/desktop/README.zh.md)负责官方展示、轮询与确认行为。

保留的可选 `reportImpact` 安全扩展仅报告 `hasDraft`、`attachmentCount` 和 `submitting`。它不携带草稿文本、附件内容、可执行文件选择或安装权限。消费方迁移必须覆盖每个已挂载 Conversation 席位与独立发送；仅声明扩展不证明端到端保护已成立。

## 考虑过的替代方案

**仅通过菜单发现更新**占用更少界面空间，但长时间工作的用户容易错过可用版本。官方账户行指示器与收起徽标现已提供该可见性，无需第二个提示栏。

**自动弹出安装对话框**更醒目，但会打断当前任务。后台发现不得授权下载、安装或重启；官方由用户发起的准备与确认保留各自的顺序要求。

**由渲染进程轮询或下载**会重复实现可信更新器，并向应用内容开放网络和包操作。Electron 保持唯一的更新执行权。

## 影响

退役的提示栏占用主面板高度，可能引起内容重排；官方展示消除了这部分重复布局开销。可用状态仍是更新状态，不是安装完成的证据。保留标量安全扩展可以继续处理输入丢失风险，而无需保留旧展示协议。

旧适配器先订阅再读取初始快照，优先采用较新事件，并在清理监听时忽略迟到完成；其编译客户端 smoke 覆盖焦点、位置、选择稍后后的保留及刷新恢复。这些观察属于退役实现，不构成官方替代实现的验收。迁移需要当前指示器/徽标、订阅清理、陈旧报告、已挂载输入和独立发送覆盖，以及单独的打包更新验收。此前任何 fixture（测试前置数据）都不证明真实版本下载，也不授权重启已安装 Desktop。
