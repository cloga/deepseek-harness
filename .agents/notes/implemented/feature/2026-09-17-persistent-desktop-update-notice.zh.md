# Agent Note: 持续可见的 Desktop 更新提示

Status: implemented

[English](2026-09-17-persistent-desktop-update-notice.md) | 中文

## 问题

仅在启动时检查会错过 Desktop 持续运行期间发布的版本。菜单入口容易被忽略，而自动弹出安装对话框会打断工作。更新状态需要一个不依赖当前会话的可见位置，同时不能赋予 Web 渲染进程包管理权限。

## 决策

Electron 负责发现版本并保存进程内通知快照。应用成功启动十秒后检查一次，此后每六小时检查一次；重叠检查会合并，确认、安装和退出期间跳过，退出时清理定时任务。后台检查不弹窗、不下载、不安装、不重启。刷新暂时失败时，保留之前验证过的可用版本提示。

应用 preload 只提供更新状态、可取消的订阅、明确的查看请求，以及原有的未保存输入影响上报。查看请求进入现有原生确认及重复的活动任务核对。渲染进程不能选择更新 URL、路径、版本或安装参数。插件管理仍只对桌面壳开放。

布局插件在主面板上方显示非模态提示栏，而不是覆盖层。切换会话或面板不影响提示；没有更新时不占空间。归 apply 所有的适配器先订阅再读取初始快照；期间收到的新事件优先于迟到的快照。其引用稳定的可观察源进入 root 注册的 inject `hooks` 分区，由框架绑定的 hook 提供普通提示属性及明确的查看回调。布局 fiber 负责清理订阅，并在释放后忽略迟到的快照、事件及查看完成结果；组件重新挂载不会再次订阅，也不会重置尚未完成的查看请求。普通 Web 和仅支持影响上报的旧 Desktop 桥接不显示提示栏。

托管更新检查在既有的版本列表读取、版本标签验证和更新清单下载边界分类已知网络错误，包括响应体读取失败。有界的 cause 检查提供本地化阶段、原因和恢复建议，不显示原始网络错误消息或 URL。未知 fetch 错误保留通用表述，不武断声称网络不可达；非网络校验错误保留原有诊断。证书建议要求保持验证开启。诊断包装保留标准的 `AbortError` 和 `TimeoutError` 名称，使仅用于构建的脱敏处理仍能识别取消类型，而不暴露原始消息。这仅改变诊断：更新来源、请求选项、重试行为和安装权限保持不变。

## 考虑过的替代方案

**仅通过菜单发现更新**占用更少界面空间，但长时间工作的用户容易错过可用版本。

**自动弹出安装对话框**更醒目，但会打断当前任务。因此，自动检查只发布状态，只有用户主动查看才打开确认。

**由渲染进程轮询或下载**会重复实现可信更新器，并向应用内容开放网络和包操作。Electron 保持唯一的更新执行权。

## 影响

提示栏占用主内容区的一小部分高度，出现时可能引起内容重排，但不会抢焦点或遮挡输入框。通知只保存在当前进程中；重启后重新检查，不把持久化提示当作已经验证的版本。后台网络错误不产生模态对话框。

针对性测试覆盖桥接限制、定时器清理、检查合并、明确确认、迟到快照和监听清理。Desktop smoke 还运行真实编译后的客户端组合，仅模拟 Electron 桥接，验证提示位置、焦点、选择稍后后的保留及刷新恢复。该测试不证明真实版本下载，也不授权重启本机已安装的 Desktop。
