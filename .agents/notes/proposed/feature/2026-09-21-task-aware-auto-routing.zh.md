# Agent Note: Host 自有的任务感知 Auto 模型路由

Status: proposed

[English](2026-09-21-task-aware-auto-routing.md) | 中文

## 问题

固定的对话模型要求调用方在理解任务之前就选择成本和推理能力。把这种选择换成三个固定模型别名，并不能实现任务感知路由。每个工具步骤都切换模型，反而可能丢失可复用的历史前缀、继承不兼容的推理强度，并让界面报告请求的模型而非实际使用的路由。

子级委派已经具有路由默认值、用户授权的显式选择，以及对缓存敏感的 fork 行为。另设独立的 Auto 选择器会产生相互竞争的优先级规则。根据少量看似成功的回答学习偏好还会带来另一个问题：便宜的简单任务和失败的困难任务，并不是可比较的模型质量证据。

## 提案

Issue #113 提议由 Host 管理 `efficiency`、`balanced` 和 `intelligence` 三种 Auto 模式，同时支持显式手动覆盖、任务范围的路由亲和性、真实的模型与原因展示，以及协调一致的子级路由。基础代码包含异步选择钩子、确定性候选策略、有界且可审计的分类器、配置解析器和初始路由状态类型。这些部分并不构成已交付的端到端 Auto 功能。下文的恢复、独立评审和个性化仍是设计要求，而非已实现能力。

Host 所有者应在提示词组装捕获提供方／模型变量之前解析任务路由。现有选择辅助函数应把同一个解析结果用于请求和路由切换通知。浏览器应提交意图并呈现已提交的事实，不得独立选择模型。LLM（大语言模型）运行时应继续负责精确路由校验和绑定注册实例的调用准备。

### 持久意图与实际使用

具体的 `model/selection` 仍表示手动意图。显式 `model/auto-selection` 应捕获所选模式以及不含凭据的候选／分类器策略，避免后续设置修改悄然改变活动任务。没有 Auto 意图的旧 Session 应保持手动模式。同步选择查询必须保持无副作用：它可以提供已配置或已固定的具体路由，但不能预测尚未完成的分类。

分类产生的是提议，而不是使用证明。实际对话请求发送时，应把任务 id、意图修订、具体提供方／模型／强度及解释绑定到已解析的请求。旧分类器稍后完成时，新的待应用手动选择必须继续保持待应用状态。新任务即使选中同一路由，也仍需要决策记录，哪怕无需写入新的请求 header。接纳失败不得发布虚构的实际路由。

新增普通事件类型可以保持现有事件载荷不变；修改现有载荷或 Session 信封仍须经过仓库的持久化评审。只读投影、冷恢复、fork 种子的归属、请求重建和未知事件处理必须一致。分类器看到的输入必须能够从精确请求审计中重建，而不能依赖后来修改的提示词模板。

### 任务感知选择与缓存亲和性

分类器只应检查受字节限制的任务文本和上一任务描述。其封闭响应描述连续性、复杂度、置信度和原因代码，绝不选择提供方或模型 id。Host 应根据配置的质量下限和相对成本权重，只从符合条件的精选提供方／模型／强度候选中选择。每种模式都必须保持任务感知：即使在 `efficiency` 中，困难任务也可能需要更强的路由；不确定证据不能成为降低活动强路由等级的理由。

工具续接、传输重试、注入上下文和后台完成通知不应各自触发分类或路由反复切换。已识别的任务应保持提供方、模型和强度。高置信度的新工作、显式用户选择或单独授权的恢复可以建立路由边界。轮次边界、压缩（compaction）事件或请求序列边界本身都不能证明出现了新任务。保持前缀可复用的条件，并不保证提供方保留或复用 KV Cache。

不修改循环的钩子会在下游 pre-step 重写之前解析已领取的输入。集成必须准确说明该分类输入，或增加用于分类重写后输入的显式接纳机制。不得悄然声称分类了分类器从未见过的已接纳文本。

### 统一的子级路由解析链

PR（Pull Request）#95 中确定性的父模型到子模型映射工作是集成依赖，不是第二个选择器，也不能证明 master 已有该行为。统一解析器必须保留显式请求／配置和提供方自有默认值的优先级，应用符合条件的确定性父级规则，仅在更高优先级规则尚未决定时使用任务感知 Auto，并以普通继承作为后备。具体路由解析完成后，获胜来源仍须可检查。

任何分支都不得绕过现有的精确路由授权、适配器强度校验、提供方能力声明、取消或提供方代次检查。被拒绝的显式选择必须失败，不能转化为另选路由的许可。注册或列出的模型并不自动获得授权。不支持子级 `agentOptions` 的原生外部提供方，不得被标注为由 Host 路由。

新建且符合条件的 spawn 子级可以获得单独分类的委派任务。fork 子级保留继承的具体路由，以保护复制的前缀。恢复的子级保留已记录的具体选择，而不是根据父级当前设置重新分类。现有子级不会被追溯加入 Auto。子级自有的任务 id 和决策不得误用继承种子中的父级任务记录。

### 可审计的辅助调用与开销

每次发送分类器调用前，都必须记录精确的生效配置、系统文本、自有消息和有界任务元数据。结算应保留有界的紧凑流前缀、封闭结果以及已观测的用量。被拒绝的超限分片和任意提供方错误详情不得进入保留结果。取消必须先结算审计状态再传播，而超时应成为显式的保守选择输入。缺失用量表示未知，而非零成本。

分类器、评审和恢复调用会增加延迟，并可能产生 API 费用。其用量必须能够单独归属，而不能改变对话上下文压力的分子。无需密钥的回放必须按实际顺序重现辅助调用，包括被拒绝和截断的结果；不得消费下一条对话响应，也不得悄然调用在线分类器。金额节省需要真实定价证据和可比较的测量，而非相对策略权重。

### 有界恢复与独立评审

拟议的恢复所有者应使用显式的尝试次数、耗时、token 和输出限制。失败应保留原始证据，标识失败路由和策略版本，并区分提供方不可用与任务结果不充分。恢复必须保留手动选择和强制授权约束。任何获准的同任务路由升级，都必须是对缓存亲和性的显式且已记录的例外，其额外工作和最终拒绝应可见。

独立评估应使用配置在不同模型路由上的全新只读评审者。每位评审者应收到同一份有界且不可变的任务、验收标准和候选结果，而不是产出 agent（智能体）的私有推理或另一位评审者的结论。评审工具不得修改文件、权限、策略或正在评估的候选结果。评审分歧、路由不可用、格式错误的结论和预算耗尽，应产生有界的未决结果，而不是无限投票循环或虚构共识。

这些评审者是拟议的设计阶段和恢复机制。使用多个模型名称，并不能证明提供方相互独立或结果正确；有利的评审也不能取代确定性测试或用户验收。

### 基于证据的本地个性化

个性化必须使用结构化的本地结果记录，而不是悄然重写提示词或把每个完成的响应当成成功。记录应标识任务类别、模式、策略版本、实际路由和强度、上下文／缓存条件、执行和评审结果、已观测用量和延迟、用户明确提供的纠正，以及测量来源。缺失或不可比较的结果必须保持未知。存储需要显式保留和导出控制；策略学习不得依赖复制不受限制的 transcript（文本记录）或凭据。

候选策略应在配置的样本量和不确定性阈值下，要求足够的可比较证据。评估必须考虑任务难度、路由可用性、提供方／模型变化和不同缓存条件；不得把简单便宜请求与困难昂贵请求视为可以互换的样本。强制授权、手动优先级、fork／恢复规则、能力限制和最大预算始终是受保护的约束，绝不是优化目标。

自适应生命周期应记录不可变的候选版本、其基线与证据窗口、有界影子评估、接受或拒绝原因，以及显式晋升。影子评估不得改变生产路由。晋升只能通过已记录的版本采纳决策影响新接纳的任务，不得修改已捕获的活动任务策略或固定子级。回滚为未来任务选择此前获批的版本，并保留历史决策和证据。证据稀疏、回归或分歧时，应继续使用最后获批的基线。

### 与现有决策的关系

取代关系检查保留[模型可见的切换通知](../../implemented/feature/2026-09-07-model-switch-notice.zh.md)、[用户授权的 subagent 路由](../../implemented/feature/2026-08-24-user-authorized-subagent-model-routes.zh.md)和[模型选择的 subagent 路由](../../implemented/feature/2026-08-18-model-selected-subagent-routes.zh.md)。这些记录的通知语义、安全决策和 fork 限制仍约束本提案。本文补充而非替代它们；没有已实现三件套符合归档条件。

## 考虑过的替代方案

**三个静态模型别名。** 它们表达偏好，却不随任务要求调整，会夸大 Auto 的含义。

**独立的子级 Auto 选择器。** 与显式／默认／父级规则解析器竞争，会使优先级和权限执行含糊不清。Auto 应位于现有解析链内。

**每次模型调用后都分类或降级。** 重复辅助调用会增加开销，并可能在一个连贯任务中使有用前缀失效。带有显式例外的亲和性更合适。

**让分类器返回任意路由。** 任务文本和模型输出是不可信输入，而候选资格和推理强度支持由 Host 负责。

**立即从回答完成或评审认可中学习。** 完成并不等于观测到了成功结果，评审投票也不是独立真值或可比较的成本证据。必须采用版本化评估和受控晋升。

## 验收标准

- 真实组合的 Session 展示每种模式内随任务变化的选择、手动覆盖、真实的待应用与实际状态展示，以及任务工具循环中稳定的提供方／模型／强度。
- 取消、组装失败、输入被拒、并发手动选择、同路由新任务、候选不可用和提供方代次变化，都保持权威意图与审计事实。
- 父级规则和 Auto 集成使用一个解析器；直接服务调用方不能规避路由授权，fork、恢复、显式子级覆盖和不受支持的传输保留所声明的行为。
- 持久恢复和无需密钥的父／子快照包含分类器请求／结果顺序、实际路由决策、失败以及可单独归属的辅助用量，并且不改变对话上下文压力。
- 有界恢复和全新只读多模型评审者覆盖分歧、格式错误输出、预算耗尽、取消和最终拒绝，同时不改变受保护规则。
- 个性化测试拒绝稀疏或不可比较的证据，固定候选和基线版本，执行不影响生产的影子评估，仅在新任务接纳时晋升，并展示不重写历史的回滚。
- 本文移至 `implemented/` 之前，文档、持久化变更记录、生成约定、定向测试和真实组合证据必须与准确的实现范围一致。

## 风险

分类和评审的成本可能超过路由选择带来的节省，也可能把任务内容发送给另一个已配置提供方，或在已有封装的情况下仍误读恶意指令。显式预算、已授权路由、精确审计和保守失败处理可降低这些风险，但不能证明模型正确。提供方缓存和内部模型别名仍不属于 Host 的保证范围。

如果削弱优先级，恢复可能掩盖真正的能力或权限失败。个性化可能放大有偏或陈旧反馈、对小样本过拟合，或引入未记录的行为变化。本提案接受更慢的晋升和更少的自动切换，以换取可检查的证据、受保护的约束和回滚。当前基础代码并不意味着这些要求已经完成。
